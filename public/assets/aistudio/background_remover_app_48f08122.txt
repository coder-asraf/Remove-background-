Professional Android Photo Editor, AI Background Remover, Passport Photo Maker & Print Studio

ROLE

Act as a senior Android application architect, Kotlin engineer, image-processing specialist, computer vision engineer, API integration developer, UI/UX designer, and automated testing engineer.

Build a complete, production-oriented native Android application named Cutout Studio.

This must be a real Android application, not a website, a WebView application, a Flutter application, or a user-interface mockup.

The final project must be compatible with GitHub repositories and GitHub Actions so that I can compile it into an APK without requiring Android Studio on my phone.

4. CRITICAL BUG FIX: ROTATION MUST PRESERVE TRANSPARENCY

CURRENT BUG:

The background is successfully removed, but rotating the image by 90 degrees causes the transparent background to disappear.

This must be fixed at the image-processing level.

Requirements:

1. Use an appropriate alpha-capable bitmap format, such as ARGB_8888.
2. Preserve the alpha channel through every geometric transformation.
3. Preserve partially transparent edge pixels.
4. Never convert transparent images to JPEG during editing.
5. Never fill transparent rotation areas with white or black unless explicitly requested.
6. Calculate the transformed image boundaries correctly.
7. Swap effective width and height when rotating by 90 or 270 degrees.
8. Support 90°, 180°, and 270° rotation.
9. Support arbitrary rotation angles.
10. Prevent unintended image clipping.
11. Prevent stretching and distortion.
12. Preserve image quality.
13. Keep the original image unchanged.
14. Support undo and redo.
15. Handle EXIF orientation correctly.
16. Avoid applying EXIF rotation twice.
17. Do not call the background-removal API again after rotation.

When the user rotates an already transparent image, transform the existing transparent image.

Do not send the original photograph back to the AI service merely because the user rotated it.

For arbitrary angles, calculate a suitable destination canvas and transform around the correct center.

Use a transparent fill when transparency is required.

Use appropriate filtering to reduce jagged edges.

Create automated regression tests for transparent PNG rotation.

Acceptance test:

Import a transparent PNG, rotate it 90 degrees clockwise, and verify that the image remains transparent, correctly oriented, and uncropped.

The application is acceptable only when:

- It is a native Kotlin Android application.
- It does not require a self-hosted server for local editing and printing.
- Local editing works without internet.
- PNG export works offline.
- JPEG export works offline.
- PDF generation works offline.
- Rotation preserves transparency.
- The live preview reflects the latest editing state.
- The PDF contains the latest rotated and cropped image.
- The print preview matches the PDF layout.
- Physical photo dimensions are correct.
- Multiple-copy printing works.
- Multi-page PDF generation works.
- Saved projects reopen correctly.
- BGNinja integration follows the verified API specification.
- API limitations are clearly documented.
- Private API credentials are not hardcoded into the application.
- Offline background removal is never falsely advertised.
- Automated tests cover the critical bugs.
- The Gradle project is complete.
- GitHub Actions can build and upload the debug APK.
- Build and test results are reported honestly.

Start by designing the project architecture and implementing the shared image-processing pipeline.

Fix the three original problems first:

1. Rotation must not destroy transparency.
2. The rotated image must appear correctly in the PDF.
3. The live preview must display the latest image state.

Then implement all remaining features.

Prioritize correctness, privacy, reliability, and print accuracy over decorative features.
